# Web 操作測試八階段實作計畫

> 規劃基準：2026-09-21。這是實作計畫，**不是已完成的測試報告**。操作定義與目前缺口見 [Web 可執行操作與測試清冊](web-operation-test-inventory.md)；高風險流程見 [核心操作測試清單](core-workflow-test-checklist.md)。

> 實作進度（2026-09-22）：第 1–5 階段已完成；第 5 階段的真實 App 測試見 `tests/app/study-session-workflows.spec.js`、`practice-session-workflows.spec.js`、`session-entry-workflows.spec.js`，條件式結果按鈕另見 `tests/visual/practice-recovery.spec.js`。各操作證據與測試層級以清冊為準。第 6–8 階段尚待實作。

## 共同規則

- 目標是清冊中每個操作都有可追蹤的測試，且測試確實執行操作並驗證結果；不能承諾零 bug。每列含多個選項或相反動作時，需逐項斷言。
- 從真實 App 入口測導航、接線與狀態；純函式、元件 fixture、視覺快照和 Emulator 各保留其擅長的保護範圍。持久化操作須驗證重新進入或重載後的結果，不只檢查 callback 被呼叫。
- 使用隔離的測試帳號／測試 project 或可控的測試 repository；**不得**碰正式 Firebase、正式使用者資料或正式 quota。外部 YouTube、Naver、系統語音以受控替身驗證本站的請求和失敗處理，不把第三方可用性當作 CI 成敗條件。
- 保留現有有效的單元測試與 24 組核心視覺快照。只在證明既有保護已被等價測試取代、並檢視差異後才可刪除或更新基準。避免每補一條操作就加一張全頁快照。
- 每個階段單獨執行相關測試及 CI 的 Web、視覺、Emulator（環境可用時）、Terminal、build；若只改測試基礎設施，也要證明現有測試沒有退化。測試失敗先分類為產品 bug、測試錯誤或環境問題，不用放寬斷言掩蓋問題。
- 每階段完成時，在清冊每個對應 ID 的「現況」填入測試檔與 **test 名稱**，符合清冊標準才改成 `通`。階段未覆蓋的 ID 不可提前標成完成。每階段獨立 commit，完成後報告通過數、仍未通過的 ID 與原因。

## 1. 建立可信的真實 App 測試入口

**對應 ID：G01–G03。** 本階段也建置所有後續階段共用的測試基礎，不以更多孤立頁面 fixture 冒充 App 流程。

- 建立測試專用的認證與資料層注入方式，讓 Playwright 開啟正式的 App 路由樹與 `AppWorkspace`；保留一條使用 Firebase Emulator 驗證認證／資料寫入合約的路徑。測試身分、快取與資料每案隔離。
- 提供可重複的 seed、資料讀取／重載、網路離線與寫入錯誤注入工具；固定日期與時間，避免今日到期題目隨執行日漂移。測試工具不得引入 production bypass。
- 先測登入成功與錯誤重試、註冊／模式切換、登出與不同帳號資料隔離。證明測試點的是真實 App；在測試模式監測並拒絕任何正式 Firebase 請求。
- **驗收**：可從登入頁走到首頁、重載後回讀測試資料；CI 在無正式憑證時可重現。關閉／移除測試替身會使相應測試失敗，證明斷言不是假陽性。

## 2. 全域導覽、首頁輕量控制與日曆

**對應 ID：G04–G06、H02、H08–H09、C01–C02。** 依賴階段 1。

- 從首頁點遍主功能標籤，檢查 route data loading；在資料夾、字幕和日期詳情測全域返回每次只退一層。更多／設定選單測開關、點外部、Esc 和命令觸發。
- 明日題數測「點擊前不計算／點擊才顯示／再點重算」。字體調整測上下界及重載；語音選擇測試聽請求、保存／取消、不支援語音的禁用狀態。
- 日曆測月份切換、今天、選取日期、雙擊及查看日期後返回。手機／桌面各選一條代表導覽流程，現有視覺快照仍獨立保留。
- **驗收**：所有列出的操作有可見狀態斷言；從 App 實際入口操作，不只測 `navigationTransition`。

## 3. 共用單字集合、單卡與資料夾

**對應 ID：W01–W11、W14–W15、W17–W18、F01–F05。** 依賴階段 1–2。W17–W18 已於功能調整中完成測試，第三階段保留回歸驗證。

- 在單字本跑搜尋範圍、熟悉度／資料夾聯集、無資料夾、排序、分頁、已學習隱藏；在資料夾和日期入口各跑一條代表流程，證明共用元件有正確接線。
- 操作單卡眼睛／全頁中文、詳情／相關詞、單字與例句韓文發音、星號、勾選及本頁多選；驗證按圖示不會誤開卡片或誤觸刪除。中文發音在學習／測驗階段驗證。匯出 JSON 檢查複製與下載的實際資料內容。
- 建立、改名、tag、釘選、收合、開啟與刪除資料夾；加入既有單字、建立新資料夾並加入、移出資料夾、清理失效 reference。用回讀區分「移出資料夾」和「永久刪除」，確認系統資料夾限制。
- 永久刪除單卡與批次刪除分別測確認／取消，驗證資料夾 reference 同步移除。高風險刪除用 Emulator 合約測試補足受控 repository 的回讀。
- **驗收**：共用控制有一組行為測試；單字本、資料夾、日期入口各有接線 smoke flow；資料歸屬和刪除語意正確。

## 4. 單字新增、編輯、JSON 匯入與日期資料

**對應 ID：H03、C04、W12、W16、E01–E08。** 依賴階段 1–3。

- 從首頁、單字本、資料夾、日期頁開新增／編輯器；手動填詞性、多個意思、例句、活用形式、補充說明、關聯詞和資料夾勾選。編輯後重載，確認內容真的改了、原作答紀錄仍在。
- 表單／JSON 切換、複製、清空、有效與無效 JSON、批次修改的檢查／返回／放棄／確認都要測。日期匯出、修改及整日刪除只能作用於當日。
- 批次匯入測缺漏／舊詞性逐筆修正、重複單字各種解法、related 缺失處理、放棄與完成。可用資料驅動案例覆蓋多種衝突選項，但每個選項需有最終卡片內容斷言。
- 保存失敗需保留輸入並能重試；使用 Emulator 證明單筆和批次寫入合約，受控 repository 測 UI 回讀。
- **驗收**：現有 `word-edit.spec.js` 的「未更動即儲存」不足以通過本階段；必須實際修改、保存、重載並查到結果。

## 5. 學習、每日測驗與所有測驗入口

**對應 ID：H01、H07、C03、W13、S01–S06、P01–P08。** 依賴階段 1–4。

- 從今日到期、單字本篩選、資料夾、日期、最不熟悉、今日錯題等入口開始；測設定頁方向、答題方式、來源、星號、順序與是否紀錄。固定時間與題目資料，避免隨機測試脆弱。
- 學習測詞性、正面語言、翻面、上一張／下一張、鍵盤、手機雙擊與磁吸、中文遮蔽、空白鍵、自動播放、發音、完整播放次數、分類切換與編輯。TTS 用受控替身斷言語言／文字／停止，不依賴裝置語音。
- 測驗分別做打字及心中自評、公布答案、答對／答錯、下一題、聲音開關、例句／文法階段揭示；完成後檢查錯題檢討、重測、今日錯題縮減與回讀排程。測不紀錄模式沒有改動每日進度。
- 對保存進度失敗及「重新儲存」補一條可恢復流程；避免只測 `sessionKeyboardIntent` 或靜態答案卡。
- **驗收**：每種 session policy 至少一條真實入口到完成／退出的旅程；共用核心只測一次，但不同持久化語意各有斷言。

## 6. 自選練習與兩類筆記

**對應 ID：H04–H06、H10、N01–N04。** 依賴階段 1、4、5。

- 自選練習測四種類型、題數／方向／文法及搜尋／熟悉度／資料夾篩選；取消不產生任務，建立失敗保留設定。開始、部分完成後重開、答對與答錯回到 pool 的差異，以及確認／取消移除。
- 筆記兩類各跑新增、編輯 tagged 文字、分類切換、搜尋、分類收合、開詳情／返回、釘選／取消、刪除與取消；重載後內容和分類正確。
- 筆記勾選、選取／取消本頁、清除、單篇與多篇練習，驗證題目來源。格式錯誤或寫入失敗時，輸入不得消失，也不得顯示成功。
- **驗收**：從首頁或筆記主頁開始的流程可完整回讀；不因單獨測過 parser 或 pool model 就將 UI 操作標成通過。

## 7. YT 字幕與閱讀測驗

**對應 ID：Y01–Y05、R01–R04。** 依賴階段 1、3、4。

- 字幕測 JSON／SRT 新增、tag、YouTube URL、已學習隱藏、搜尋、收合、編輯／刪除及重載。播放器用 stub 的 iframe API 模擬時間、播放／暫停、點句跳轉與自動捲動；另測無影片及播放器錯誤提示。
- 滑鼠與手機觸控選字測句首、範圍調整、查字典連結、快速新增、全句新增、暫停影片、highlight、意思泡泡、編輯／刪除已建單字。測中文切換不改字幕卡高度與資料夾泡泡的條件顯示。
- 閱讀測驗測複製格式、批次 JSON 匯入、搜尋、tag 收合、編輯／刪除、已學習切換、答對／答錯與重做。文章、題目及選項的中譯要在公佈後各自出現。
- 閱讀選字新增／查字典／臨時畫線／取消／已建字詳情與編輯刪除，驗證與字幕共用元件的接線差異。外部連結只檢查本站產生的 URL 與新分頁設定。
- **驗收**：新增或編輯後重開仍可見；播放器同步由受控時鐘測試，不讓 CI 依賴真實 YouTube。

## 8. 離線、失敗復原與完整盤點

**對應 ID：G07–G08、O01–O04。** 同時對前七階段做全量稽核。

- 主動離線、下載／更新與完整重建、離線新增／編輯／刪除／每日作答、恢復連線同步。回讀確認沒有重複或遺失，換帳號不看到前一帳號快取。使用受控網路與 Emulator，不碰正式資料。
- 寫入拒絕、429、斷線、同步延遲與重試至少各有一個代表流程；渲染錯誤測錯誤資訊、返回與重載。不得出現永久「同步中」或虛假成功。
- 逐項核對清冊全部 **84 個 ID**（若期間新增功能，總數同步增加），確認每列的各個選項都有測試名稱、實際斷言及必要的保存回讀；抽查測試注入失敗時確實會變紅。
- 跑完整 CI，評估測試時間、易碎度與既有快照；只在有明確等價替代時移除測試。將可重複的失敗修為產品 bug 或測試 bug，不把清冊未通項目默默略過。
- **驗收**：所有清冊 ID 為 `通`，且證據能追到 test 名稱；測試沒有正式服務依賴。這表示已達約定的**操作覆蓋標準**，不表示所有可能環境與資料組合皆無 bug。
