# 核心操作測試清單

> 盤點基準：2026-09-21，commit `9c81830`。本文件記錄測試缺口與驗收方式，不代表目前勾選項目已完成。

## 目的與判準

現有測試對解析、排程、共用元件和靜態排版有保護效果，但瀏覽器測試主要開啟 `visual-fixtures.html`，未經過真正的 `AppWorkspace` 路由、資料 hook、寫入與重新讀取。後續的核心操作測試必須驗證「入口 → 操作 → 寫入 → 重新開啟後的結果」，不能只確認按鈕存在、callback 被呼叫或初始畫面看起來正確。

- 使用假的登入身分、可控的 repository 或本機 Firebase Emulator；不連正式 Firebase，不消耗正式資料庫 quota。
- 保留純函式測試處理排程、解析、篩選等規則；完整流程只選高風險的代表案例，不為每個按鈕重做一套 E2E。
- 每項完成後，測試須從真實頁面入口開始，依可見文字／角色操作，並在重新進入頁面後確認結果。若使用 fake repository，另以少量 Emulator 測試驗證寫入合約。
- 成功和失敗路徑都要覆蓋：保存失敗要有明確提示，不能顯示成功或無限停在載入／同步中。
- 下列「現有覆蓋」只表示已有部分保護，不等於完整流程通過。

## 快照與現有測試評估

**本次不刪除任何測試或快照。** `core-surfaces.spec.js` 的 8 個畫面各有 360px、390px、desktop 快照，共 24 組；本機 Linux 與 CI Playwright 容器分別保留基準。它們雖不能證明保存功能，但仍能抓到韓文被按鈕擠壓、手機水平溢出、卡片高度和字幕區域位移等曾發生的回歸。各畫面也不是完全相同的像素輸出，沒有證據顯示某組已失效。

| 測試範圍 | 仍有的保護效果 | 不應被誤認為 |
| --- | --- | --- |
| 單字卡、單字本、資料夾快照 | 共用卡片及集合頁在三種寬度的排版一致性 | 新增／編輯／資料夾保存已成功 |
| 學習、測驗快照 | 翻面、答案區及控制列的可見性和尺寸 | 完成一輪後進度、錯題及返回正確 |
| YT 字幕、筆記、閱讀快照 | 長文字、影片／字幕版面、內容列表及閱讀答案版面 | 新增、編輯、選字及播放器同步正確 |
| `error-boundary`、`word-edit`、`word-pos-import`、`youtube-embed` | 特定控制項與錯誤畫面的互動保護；不是上述 24 張靜態快照 | 完整的登入到資料庫回讀流程 |

只有在證明某快照的內容、尺寸及斷言與另一測試等價，並有替代測試保護原本的風險時，才考慮移除。更新快照必須檢視 diff，不能因 CI 失敗就直接覆蓋。若新功能只改變資料或操作，不應機械式增加全畫面快照；選擇行為斷言或局部截圖即可。CI 容器使用 `playwright-1.63-noble` 基準，本機使用 `linux` 基準；兩者更新需分別確認。

## 實施順序

1. 先建立不使用正式帳號的真實 app 測試入口，讓測試能跑 `AppWorkspace` 的路由與資料接線。這是目前 fixture 最大的缺口。
2. 先完成 P0 中單字新增、筆記新增、資料夾學習／測驗、每日作答與 YT 選字五條 smoke flows；每條都驗證回讀與錯誤訊息。
3. 擴展到其餘 P0／P1，對需要驗證遠端寫入合約的少數流程接 Firestore Emulator。純畫面測試持續使用 deterministic fake，不依賴 YouTube 或正式 Firestore。
4. 每補上一條完整流程，再審視相鄰的靜態／原始碼比對測試是否真的重複；沒有等價替代之前不刪除。

完成標準：CI 能在部署前攔下「畫面可開、但無法新增／修改／完成學習或測驗」這類回歸，同時保留有用的視覺保護，且不增加正式 Firestore reads/writes。
